# Contributing

Keepsake Atelier is a small macOS-first project. Bug reports, logs and pull
requests are welcome, especially from people with a drive the project has not
seen.

## Before you start

- Read [docs/guides/install.md](docs/guides/install.md) and run
  `keepsake-atelier doctor`. Most "it does not work" reports are a missing
  library or a drive behind a hub.
- Search the existing issues. If you are reporting a rip or burn failure, include
  the output of `keepsake-atelier doctor --json`, `keepsake-atelier disc` and the
  last lines of the job log.
- Do not paste a KEYDB file, a VUK, a disc key or a unit key. They are not needed
  to debug a tree check or a build.

## Build

```sh
cargo build --release
cd app && npm install && npm run tauri build
```

The engine and CLI are the source of truth. The desktop app calls the same core
functions through Tauri commands; a feature that only exists in the UI is not
finished.

## Test

```sh
cargo test
```

The suite covers the navigation writers, the BDJO writer, menu parsing, UDF
sizing, key derivation fixtures, burn command construction and the TV planner.
Tests that need a disc or a drive are intentionally absent; use
`scripts/mkbd.mjs` for a synthetic tree.

The BD-J menu asset has its own check:

```sh
scripts/test-menu.sh
```

It runs the real Xlet in a stubbed BD-J harness and writes screenshots.

## Code style

- `cargo fmt` before committing. `cargo clippy` is welcome but not enforced.
- Keep the CLI, MCP tools and app cards in sync. A user-facing capability should
  be reachable from all three.
- Destructive operations need a dry run, a confirmation, or both.
- Do not add a dependency that duplicates a macOS built-in unless the built-in
  cannot do the job. The project deliberately uses `newfs_udf`, `hdiutil` and
  libbluray rather than bundling duplicate toolchains.

## Docs

- User-facing pages live in `docs/` and are linked from the README.
- The site is `docs/index.html` plus `docs/site/`. No build step.
- The download table and `docs/downloads.json` are generated by
  `scripts/publish-release.sh`. Do not hand-edit inside the
  `<!-- downloads:start/end -->` markers.

## Release process

The maintainers publish with:

```sh
scripts/publish-release.sh
```

That builds the DMG and CLI tarball, uploads to GoFile and file.kiwi, patches the
links, commits and cleans up. The weekly launchd job runs the same path. See
[docs/publishing.md](docs/publishing.md).

## Reporting a security issue

Do not open a public issue for a key-handling or sandbox escape problem. Send a
direct message on the [Discord](https://discord.gg/SUaUrVGj5f) to a maintainer and
include the smallest reproduction you can.
